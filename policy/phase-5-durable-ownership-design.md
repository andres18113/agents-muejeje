# Phase 5 internal design summary

1. **Coredo invariants.** Reserve capacity before granting write access; publish complete, versioned records atomically; validate durable state strictly; bind liveness to PID plus process start identity (and a process group where one exists); distinguish observational leases from custody; preserve orphaned work; and fail closed whenever state, liveness, or ownership is ambiguous.
2. **Pact invariants.** Serialize Git worktree mutation; capture the base commit at creation; persist workspace and agent-process metadata outside the checkout; detect PID reuse with process start time; make teardown possible from another process; refuse dirty-worktree destruction by default; use process-tree termination rather than a direct-child kill; and treat SQLite leases as advisory rather than authoritative ownership.
3. **Adopted here.** One durable owner per canonical repository identity; `RESERVED` with `accessMode:none` before preparation; strict state transitions; PID plus start-time identities for both coordinator and Claude; reconciliation only after identity evidence; detached Git worktrees for `general-purpose`; root-bound `task`; retained completed/orphaned worktrees; exact-child terminal proof in the live coordinator; and a fresh start-identity match before `taskkill /PID /T /F`, followed by an exact-child terminal event for forced Windows termination.
4. **Deliberately not adopted.** No persistent workers, parallel writers, automatic merge/commit/push, dirty-tree snapshotting, advisory file leases, relational coordination data, process-name discovery, native Job Object dependency, or automatic orphan/worktree deletion. Pact's broader workspace/merge architecture and Coredo's PTY/session topology do not fit this MCP's fresh-process contract.
5. **Storage.** Use schema-versioned JSON inside an atomically renamed ownership directory under the per-user local application-data directory, keyed by SHA-256 of the canonical repository identity. Atomic directory rename supplies cross-process no-replace admission; atomic JSON replacement supplies inspectable transitions. This is smaller than SQLite/WAL, avoids a Node 20 native dependency, and is sufficient for a single authoritative record per repository. Malformed authoritative state blocks admission.
6. **Windows process identity.** Query `Get-Process -Id` through Windows PowerShell and emit only invariant creation-time ticks, with structured exit statuses rather than localized text parsing. Compare `{pid,startTime}`: matching means the same live process, a missing PID means dead, a live PID with different ticks means reused/dead owner, and query/access/format failure is ambiguous. Ambiguity blocks. This implementation makes no cross-platform process-identity guarantee.
