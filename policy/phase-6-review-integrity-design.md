# Phase 6 review-integrity design summary

1. **Question answered.** Phase 5 establishes who may write. Phase 6 establishes exactly which Git-visible repository state a review result can be bound to. Reviewer prose remains advisory; mechanical repository evidence and deterministic gates remain authoritative for what they exercise.
2. **One admission boundary.** Coherent reviews reuse the Phase 5 atomic rename onto `ownership/` with `custodyKind: "coherent-review"`. Writers and reviewers resolve the same Git-common-directory coordination identity. There is no second lock, acquisition order, lease, TTL, or heartbeat.
3. **Truthful interval.** Admission is taken before BEFORE collection and released only after AFTER collection and receipt publication has quiesced. The `REVIEW SUBJECT` block is composed before the reviewer runs, when the only true statement is that admission is held at that instant, so its wording says exactly that and adds that survival across the interval is verified afterwards - never that coherence already covered the review. Denied admission states plainly that the review is advisory and that managed writers may be modifying the repository. Only a successfully bound receipt records verified coherence for the completed interval.
4. **Graceful denial.** A writer, another review, malformed ownership state, or ambiguous identity may deny coherent admission. The review still runs read-only as advisory output, persists no receipt, and reports unavailable/unbound evidence without changing its execution status.
5. **ChangeSet identity.** `cs1:` hashes the canonical object format plus section digests for head, target, policy, index, worktree, unmerged paths, untracked paths, and submodules. Receipt validation recomputes this derivation rather than trusting the stored identifier. Git porcelain-v2 `-z` supplies structural state; exact filesystem bytes supply changed-content identity. Summary branch, merge-base, and counts never enter the identity. Only the literal `branch.oid (initial)` yields an unborn HEAD; a missing, malformed, or wrong-width `branch.oid` is indeterminate, because absence of a header is not a claim that the repository has no commits. Encoded descriptor paths are identity and display representations and never filesystem locators: a non-UTF-8 path is addressed by raw Git path bytes where the platform can address them and is indeterminate where it cannot, so a file literally named with another path's hexadecimal spelling can never be hashed in its place.
6. **Binary and race posture.** Status, filenames, regular-file bytes, and link-target bytes stay binary-safe until deliberate display encoding. The bracket covers every identity-bearing observation, not only porcelain status: one collection observes status, then the resolved review target, then the resolved worktree HEAD of every clean submodule, collects content, and re-observes all three in the same order, requiring each pair to agree. A moved target ref and a clean submodule moved between two non-index commits both change the subject while leaving porcelain output byte-identical, which is why status equality alone is insufficient. Per-file double-stat brackets detect content churn. Persistent disagreement exhausts the bounded attempt budget and is reported as `collector_unstable`; this is bounded observational consistency, not snapshot isolation.
7. **Explicit target.** `ReviewTargetSpec` is durable intent with request, retained-worktree, or unspecified provenance. `ReviewTargetContext` resolves that exact fully-qualified ref independently for every collection. No upstream or default-branch inference exists.
8. **Canonical representation.** The local canonical-JSON implementation accepts only the deliberately narrow plain-data domain, sorts object keys by UTF-16 code unit, rejects lone surrogates and unsafe/non-integer numbers, and uses exact UTF-8 bytes for digests. ChangeSet hashed sections contain no numbers.
9. **Receipt basis.** `rr1:` covers the entire canonical receipt body with `reviewId` absent during derivation. Text contracts, assignments, and results use exact UTF-8 SHA-256 without trimming or normalization. Capability policy uses canonical JSON. Assignment records SHA-256 and JavaScript character count; result records SHA-256 and UTF-8 byte count. Reviewer basis records the requested model selector and source, model strategy, and reasoning effort, never an unproved effective served model. The binding records the two observations' non-identity metadata separately as `beforeSummary` and `afterSummary`, because the reviewer saw only the BEFORE summary and a single undifferentiated field filled from AFTER would present metadata it never saw as its subject; neither is hashed into `ChangeSetId`.
10. **Immutable evidence.** Authoritative receipts are create-once files at `reviews/cs/<change-set-prefix>/<review-prefix>/receipt.json`, staged in a nonce-named temporary directory and renamed into place, so a receipt is durable before anything points at it. The system never rewrites, renames, or deletes them; an identical write is idempotent and a differing one under the same truncated prefix is refused as a collision rather than merged. A full self-recomputed ID, not the truncated directory prefix, decides identity. Corrupt entries are reported and preserved. Publication is fenced: cancellation before the write is issued permanently removes the authority to publish, and a write already issued must quiesce before coherent-review custody is released - an unquiesced write retains the slot instead, because a timeout observes uncertainty and never proves the write stopped.
11. **Stable stale discovery.** Lookup cannot depend only on the current `ChangeSetId`, because that makes historical stale evidence unreachable. A bounded `reviews/sc/<stable-scope-prefix>/<zero-padded-timestamp>-<review-prefix>.json` index uses stable scope (reviewer type plus declared target ref) to point to immutable receipts; the zero-padded timestamp makes lexical order chronological, so newest-first discovery and oldest-first pruning need no reads. Pointers are explicitly non-evidentiary, bounded, and prunable; their identifier shapes and the loaded receipt's full scope are checked, and every referenced receipt is validated before freshness evaluation. Index failure never changes already durable evidence.
12. **Three-valued freshness.** Freshness is computed, never stored. Equal exact subject IDs are `FRESH`; comparable different IDs are `STALE` with changed-section reasons; corrupt receipts, indeterminate current collection, or schema mismatch are `INDETERMINATE`. Review basis differences are informational and never change this repository-state verdict.
13. **Crash behavior.** Coherent-review records use the unchanged Phase 5 transition and reconciliation rules. A crash before receipt persistence leaves no evidence. A crash after persistence leaves an immutable valid receipt while stale ownership reconciles normally. Ambiguous identity retains the slot and blocks admission.
14. **Privacy and authenticity.** Receipts store digests, counts, lifecycle/provenance metadata, section digests, and target context. They store no contract, assignment, result text, environment, secret, absolute path, or changed path. They are unsigned and provide content integrity, not authenticity.
15. **Git lessons adopted.** Porcelain-v2 `-z` record grammar and two-field rename parsing are adopted for byte-safe observation. Git object IDs are used where Git already defines indexed content; worktree-only bytes are independently hashed. `git write-tree`, index refresh, checkout, and object creation are rejected because collection must remain observational.
16. **Review-system lessons adopted.** Gerrit's revision-keyed approval and derived outdated-ness motivate immutable state-bound receipts and computed freshness. in-toto's digest-bound subject and configuration digests motivate explicit content-addressed evidence, while its permissive unknown-field rule is rejected in favor of exact keys. JCS ordering motivates canonical bytes, with a narrower supported value domain. jj's Commit-ID/Change-ID distinction reinforces that Phase 6 needs an exact observed-state identity, not a mutable change-series identity.
17. **Deliberately deferred.** No DSSE/signatures, carry-forward object, review series, working-copy snapshot commit, recursive dirty-submodule identity, sparse-checkout identity, retention service, parallel review readers, native process containment, or Phase 7 orchestration is introduced. No canonicalization dependency is added.
18. **Honest scope.** The guarantee excludes unmanaged writers, ignored files, undetectable change-and-revert races, cross-machine portability, receipt authenticity, and review quality. `changeSetId` is a local worktree-state identity; a receipt says what completed under verified managed-writer exclusion, not whether the review was correct.
19. **Module boundaries.** Phase 6 adds modules with single responsibilities and no reach beyond them. `changeset/porcelain-parser` knows the `--porcelain=v2 -z` grammar and nothing about review; `changeset/path-locator` owns the one rule that an encoded path is never a pathname, and is the only place that decides raw-byte addressability per platform; `changeset/workspace-digest` owns exact-byte content hashing and the double-stat bracket; `changeset/target` separates durable `ReviewTargetSpec` intent from per-collection `ReviewTargetContext` observation and derives the stable review scope key; `changeset/descriptor` owns identity and is pure; `changeset/collector` owns the bracket, the refusal vocabulary, and cancellation. On the review side, `review/receipt-basis` measures non-repository basis, `review/receipt-schema` defines what a receipt legally is, `review/receipt-store` owns the two trees, `review/publication-fence` owns the durable publication boundary, `review/freshness` computes verdicts without storing them, `review/coherent-admission` reuses the Phase 5 rename, `review/target-provenance` resolves inherited targets by name, `review/review-subject` composes reviewer-facing evidence, and `review/review-binding` sequences BEFORE, reviewer, AFTER. Only `delegate-agent` orchestrates; none of these modules releases custody or decides delegation status.
20. **Collection cancellation.** The collection deadline cancels the collection as well as the caller's wait. After it fires, no new Git command and no new filesystem read begins. This is observational and fail-closed: it stops further evidence gathering, and it is never treated as proof that in-flight work has stopped or that the workspace is quiescent.
